# Character 首屏神谱技术方案

日期：2026-09-01  
状态：首版已实现并完成本地 Light / Dark 交互验证；性能预算仍需以生产内容规模复测。

## 1. 选型结论

采用 **3d-force-graph + Three.js + Astro 原生 TypeScript 客户端组件**。

本方案替代讨论阶段的 G6 / 二维 force-graph 首选建议。目标是在角色首屏提供有空间纵深、镜头聚焦和克制光晕的神谱探索体验，同时保留关系的可读性、来源和传统范围。默认是真实三维关系网络，不将三维能力限制为二维家谱。

不引入 React、React 图谱包装层、G6 或另一套并行渲染器。3d-force-graph 负责图形与交互，不负责决定神话事实；关系数据独立于渲染器。

官方已提供图片节点、关系高亮、聚焦、增量数据、曲线、方向箭头、后处理和暂停/恢复能力。自动避让所有投影标签、关系语义分层和传统筛选需要应用自行实现，不能视为框架自带。

## 2. 首版页面范围

- 在 `src/pages/character/[slug].astro` 移除 `CharacterDNA` 与 `CharacterRelations` 的页面展示，保留组件文件和 Canonical Design / 关系数据。
- Hero 的“查看作品”后增加“查看神谱”及 Lucide `ArrowRight`。
- 神谱只覆盖 Hero 区域，保持 Hero 高度和顶栏位置，不弹窗、不默认导航到新页面。
- 作品筛选、下载/创作入口、相关推荐、URL 参数、SEO 元数据保持不变。
- Light / Dark 共用尺寸、结构、相机规则与控件位置；只调整语义色、底景、光晕强度。
- 详情页同时考虑桌面和移动端；角色列表不在改动范围内。

## 3. 状态与转场

状态：`intro → loading → graph`；加载失败进入 `error`，任何状态均可返回 `intro`。

1. 点击入口后加载图谱模块，左侧文案与 CTA 淡出；在同一区域提供简洁加载状态。
2. Hero 图片提高透明度，即降低图片 opacity；仅操作图片/遮罩层，不降低整个 Hero 的 opacity。
3. 透明 WebGL Canvas 在 Hero 内淡入；第一次展示完成相机取景，避免先出现远处一团小点再突然放大。
4. 左上角显示 Lucide `ArrowLeft` 与“返回角色”。返回或 Escape 恢复原始文案、背景和入口焦点。
5. 连续点击、加载中退出、退出后重进均需要明确取消/复用策略，旧异步结果不得重开已关闭图谱。
6. 文案淡出期间使用适当的 `inert` / 可访问状态，避免用户点到或聚焦不可见按钮；图谱未启用时不拦截页面输入。

淡出约 200–300ms、淡入及镜头过渡约 400–700ms，仅为初始设计值。减少动态效果偏好下关闭镜头飞行与装饰动效。

## 4. 三维视觉与可读性

### 节点

- 当前角色用明确的肖像、姓名和柔和外环作为视觉锚点。
- 直接关联角色用较小肖像/星核与姓名；按投影空间决定标签显示优先级。
- 次级角色适当降低视觉权重；选中或聚焦后提升为可清晰阅读的节点。
- 肖像使用朝向相机的 Sprite，避免旋转后变成背面卡片。无已审核肖像时回退到文字/品牌允许的意象，不生成虚假的角色资产。
- 3D 避碰不能保证屏幕上的文字不重叠。优先保留当前/选中/直接关联节点标签，提供 HTML 信息区和文字关系入口作为补充。

### 连线

- 默认细线、低强度光感；选中人物后突出直接关系，淡化无关关系。
- 关系名称优先显示在选中的连线及信息区，不在所有空间位置铺满文字。
- 有方向的边显示正确箭头；配偶、同伴等对称关系不因为存储方向而误加语义箭头。
- 同一对角色的不同关系通过曲率/旋转角分离，不能按人物对合并为一条事实。
- 方向粒子只用于需要表达方向的选中关系；首版不全图持续流动。

### 相机和动效

- 使用 Orbit 控制，保留旋转、缩放、平移；设定合理的视距与角度边界，避免穿入节点或翻转后失去方向。
- 初始相机以当前角色的局部关系取景；进入时可有一次缓慢推进，默认不长期自动旋转。
- 点击人物进行镜头聚焦和关系信息更新；首版提供“展开二度关系”。聚焦与扩展分开，避免每次点击都重排整图。
- 始终提供“回到当前角色”；该操作复位图谱，不等同于左上角退出神谱。
- 增量展开时保留旧节点 ID、位置与速度，新节点从关联位置附近加入，以有限模拟完成排布。
- 父母/师承筛选可在后续提供语义布局，但不得将“位于上方”同时解释为父母、老师和统治者。

## 5. 背景与光晕策略

- 框架允许带 alpha 的 WebGLRenderer；透明背景配置由组件显式设置，使现有 Hero 原画透出。
- 首版优先使用可控的 Sprite 光晕。Bloom 作为增强项，不能直接照搬官方深色全背景示例。
- 引入 Bloom 前必须验证 alpha 合成、肖像与文字清晰度、Light/Dark 表现以及 GPU 开销；不通过则保留 Sprite 光晕。
- Light 使用玉白、淡金和清晰轮廓；Dark 使用墨蓝底景、月白、克制金光。Light 不自动切成全黑星空。
- 不以高强度发光掩盖图谱过密、标签不可读的问题。

## 6. 数据与中国神话扩展

直接复用 `CharacterRelation` 与关系仓储，不新建 family-tree table。

- 支持有向关系、多关系、来源、`traditionScope`、`from/toInterpretationId`、`confidence` 和 `isDefault`。
- Character、CharacterInterpretation 与 CharacterVariant 不混用；艺术 Style 不影响神谱关系。
- 关系端点可以是 Character 或已有 ContentConcept，呈现时区分类型；不将概念伪装成人物。
- 亲缘、师承、统属、盟友/同伴、冲突、身份关联按语义分组。首版只展示有实际数据的筛选项。
- 不将多个相互矛盾的传统同时画成一组确定事实。默认关系需在兼容的解释范围内选择；异说提供来源说明和切换入口。
- 亲子统一读取父母指向子女的语义；兼容遗留逆向类型时先归一化。现有列表中父母页面仍把子女标成“父母”的逻辑不得沿用。
- BFS 只用于选取邻域，不得把路径距离解释成辈分，也不得依据同属一个 Realm 推断亲属/盟友关系。
- 原始关系数据保持不变；传给力学引擎的是独立 DTO。引擎可能将端点 ID 替换为节点对象并写入位置，不能污染仓储对象。
- 默认直接关系为主，按需补充二度上下文。建议桌面初始上限约 24 个节点、展开上限约 80 个；移动端更少。这些是待实测的产品预算，并非框架性能保证。
- 触达上限必须显示“还有 N 个关系待展开”等明确信息，不能静默丢失关系或声称展示了全部神谱。
- 整个文明的全量图谱属于后续独立入口，复用数据，但不随角色详情首屏全量下发。

## 7. Astro 集成边界

拟议文件职责：

| 文件 | 职责 |
| --- | --- |
| `src/pages/character/[slug].astro` | 页面组合、移除旧模块展示 |
| `src/components/character/CharacterHero.astro` | 原文案、背景、入口、状态切换、延迟加载 3D 渲染器与销毁 |
| `src/lib/content/character-graph.ts` | 传统范围选择、邻域截取和渲染安全 DTO，不含绘制代码 |
| `src/pages/api/character-graph.ts` | 有限范围获取公开节点、概念和关系，校验焦点/深度/数量参数 |
| `src/lib/content/repositories/content-concept.ts` | 按已公开关系端点读取 active 概念 |

页面继续 SSR，图谱依赖使用客户端动态 import，首次点击才初始化；不让 Three.js 进入 Worker 执行路径。初始关系文字/链接服务端渲染，图谱失败或禁用 JS 时仍可获取核心关系内容。

安装时选择并锁定经验证的 `3d-force-graph` / `three` 兼容版本，核验单一 Three.js 实例。不要混用 CDN Three.js 与 npm 依赖，也不要直接复制参考项目的包装类型或旧版初始化调用。

## 8. 性能、安全与恢复

- 进入时懒加载，退出、离开视口和标签页隐藏时暂停；恢复时重新启用交互。
- 力学模拟冷却与停止 WebGL 渲染是不同动作。可见且可交互时不能无条件调用 `pauseAnimation()`，该方法也会暂停交互。
- 页面离开时清理事件、ResizeObserver、计时器、渲染循环和资源；销毁自建纹理/材质/几何体，验证多次进出没有持续增长。
- 首版限制 DPR 与纹理分辨率，共享可复用纹理；Hero 的原始大图不能直接成为每个节点的纹理。
- R2/CDN 图片作为 WebGL 纹理时需要验证 CORS，不能仅凭普通 `<img>` 可显示就认定可用。纹理失败单节点回退，不阻断整个图谱。
- 关系名/来源名用安全文本节点展示，不拼接未经转义的 HTML tooltip。
- 无 WebGL、context lost、模块加载失败、接口失败均有文字关系回退、重试或返回入口；空数据展示当前角色与“暂无已收录关系”。
- 移动端保护正常页面滚动，限定图谱手势作用范围；支持明确的平移/缩放/复位按钮及键盘替代操作。

## 9. 验收与风险

实现后必须完成：

1. 两轮浏览器截图比较：桌面 Light/Dark 的原始 Hero、打开神谱、聚焦、返回；同时验证移动端。
2. 清晰读出当前人物、直接关系、选中关系方向与来源；双亲、多关系、争议传统、不连通节点不产生错误语义。
3. 测试加载中退出、快速重复开关、重新进入、切换主题、窗口缩放、页面离开与重新访问。
4. 验证透明背景与光晕合成；不通过时关闭 Bloom，而不牺牲首屏底景与文字可读性。
5. 测量动态 chunk、加载耗时、交互帧时间与多次进出后的资源占用；节点预算依据实测调整，不预先承诺固定 FPS。
6. 模拟模块/图片/接口失败和 WebGL 不可用，保证原始角色页与作品浏览仍然可用。
7. 执行 `npm run check`；数据转换与关系语义变化执行 `npm test`，覆盖方向、来源、截断、增量展开与 DTO 隔离。

已完成本地桌面 Light / Dark 的 Hero、进入神谱、二度展开和返回验证；`npm run build`、关系 DTO 测试已通过。生产规模下仍需根据真实中国神话节点数量复测加载耗时、帧时间和资源占用。
