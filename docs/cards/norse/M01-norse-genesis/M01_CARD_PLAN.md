# 1. 10 位数字 Card ID

统一格式：

```text
CC MM SS TT NN
10 03 01 00 01
```

| 段 | 当前值 | 含义 |
|---|---:|---|
| Category | `10` | 收藏卡 |
| Mythology | `03` | 北欧神话 |
| Series | `01` | M01《北欧创世》 |
| Style | `00` | 当前默认风格 / Primordial Saga |
| Card No. | `01–50` | 本系列卡牌编号 |

最终范围：

```text
第 01 张：1003010001
第 02 张：1003010002
...
第 50 张：1003010050
```

完整 Card ID 使用数字存储：

```text
DB: BIGINT
JSON: integer
JS/TS: number
```

不再维护独立 `Content Key`。

同一内容卡跨 Style 的稳定身份，直接由以下字段共同决定：

```text
Category + Mythology + Series + Card No.
```

例如：

```text
1003010001  Style 00
1003010101  Style 01
1003010201  Style 02
```

三者均代表 M01 第 01 张内容卡，只是视觉风格不同。

# 3. 核心构图原则：壁纸完整 + 天然可裁卡

所有 48 张竖图都必须满足：

> **主体上移，身份信息集中在画面上半部；底部和左右边缘允许未来裁切或被卡面信息区遮挡。**

## 3.1 Critical Identity Zone

```text
X：20% ～ 80%
Y：12% ～ 52%
```

优先容纳：

- 角色脸；
- 核心身份 Symbol；
- Story Action 高潮；
- 神物关键结构；
- Scene 第一地标。

## 3.2 Primary Subject Zone

```text
Y：10% ～ 66%
```

主体主要视觉关系应在这一区间内完成。

## 3.3 Sacrificial Bottom Zone

```text
Y：70% ～ 100%
```

只放可牺牲信息：

- 地面；
- 水面；
- 根系末端；
- 腿部下段；
- 衣摆；
- 雾 / 火花 / 碎屑；
- 非关键前景。

未来即使底部被卡名、描述区遮挡或裁掉，也不得破坏主体身份和故事理解。

## 3.4 Crop-Tolerant Side Zones

```text
X：0% ～ 14%
X：86% ～ 100%
```

只放可延展内容：雾、云、枝叶、地貌、光效、非关键背景。

禁止把脸、关键手部、关键神器、关键动作终点放进左右边缘区。

## 3.5 各类主题默认主体位置

### Character

- 脸默认位于 `Y 22%–34%`；
- 胸肩 / 核心 Symbol 位于 `Y 30%–50%`；
- 允许腿部进入底部可牺牲区；
- 不为了全身像把脸压到画布中下部。

### Story

- 主要动作中心位于 `Y 20%–55%`；
- 关键角色关系尽量在中上部建立；
- 下方承担地面、海面、碎屑和前景。

### Scene

- 第一地标放中上区域；
- 底部主要作为进入场景的前景；
- 裁掉底部后仍能识别地点。

### Mythic Object

- 核心结构位于 `Y 20%–58%`；
- 关键徽记、功能结构不得落在底部 30%。

### Ensemble 横版

- 核心角色群 / 世界地标集中中央约 70%；
- 四边保留可延展环境；
- 便于网站 Hero 和未来横卡重新裁切。

# 8. 五类 Artwork 设计语言

## Character

- 单角色优先；
- 背景属于真实故事语境；
- Pose 体现身份，不站桩；
- Character Canon 比特效重要；
- 主体身份必须在上半部成立。

## Scene

- 地点本身是主角；
- 人物只做尺度参照；
- 每个 Scene 必须有唯一结构；
- 核心地标裁掉底部后仍清楚。

## Story / Key Moment

- 一张只讲一个主要动作；
- 不做漫画分镜；
- 不拼时间线；
- 动作高潮尽量位于中上部。

## Mythic Object

- 物件是主角；
- 不做游戏装备栏；
- 核心物件完整结构位于安全区。

## Hero / Ensemble

- 系列海报级；
- 横版 16:9；
- 多元素处于一个统一世界状态；
- 禁止人物立绘拼贴。

> **在冰与火第一次相遇的原初鸿沟中，尤弥尔作为“尚未成形世界”的巨大生命显现。**

## 11.2 构图

```text
方向：9:16 竖版
镜头：low angle / 低机位
景别：full-body / 全身，但上半身是视觉中心
主体 Anchor：约 X 50%, Y 30%
脸：Y 18–28%
上胸 / 肩：Y 25–45%
腿和脚：允许进入 Y 70–100% 可牺牲区
```

## 11.3 Ymir Canon

必须：

- 体型具有世界级尺度；
- 身体像自然物质而不是怪兽盔甲；
- 皮肤呈霜、湿岩、冰、水汽混合质感；
- 整体灰白 / 岩灰，不能默认蓝皮；
- 无维京盔甲、无王冠、无武器；
- 不是普通肌肉巨人；
- 面部古老、沉静、原初，不要恶魔化。

## 11.4 环境

```text
左 / 冷侧：Niflheim 的冰雾、寒流、灰蓝光
右 / 暖侧：Muspell 的火星、暗橙热光
中央：Ginnungagap 的黑暗、蒸汽、融滴
底部：雾、冰水、未成形地表，可裁切
```

不画成熟世界、城市、宫殿或维京建筑。

## 11.5 Style 00 视觉目标

- painterly，而非照片；
- 高端神话概念艺术，但不过度游戏 CG；
- 宏大尺度；
- 材质细腻但不堆机械细节；
- 克制火光 / 冰光；
- 画面有艺术插画感，不做游戏宣传海报；
- 纯画面，无任何文字和卡面 UI。

# 12. 出图前 Gate

### Naming Gate

- Category Code = `10`；
- Mythology Code = `03`；
- Series Code = `01`；
- 当前 Style Code = `00`；
- Card No. = `01–50`；
- 当前 Card ID = `1003010001–1003010050`；
- Card ID 使用 BIGINT / number；
- 不存在独立 Content Key。

### Content Gate

- 50 个主题锁定；
- P0 Source Scope 锁定；
- 缺失 Character / Scene / Object 补齐或明确替换。

### Composition Gate

- 每张竖图定义 `criticalIdentityZone`；
- 每张定义 `cropSafe`；
- 核心主体上移；
- 底部 30% 被遮挡时仍能看懂；
- 左右边缘裁切时不损失关键身份。

### Artifact Gate

- 每张 JSON 先建档；
- JSON 通过 Schema；
- Prompt / Canon / Composition 完整后才允许调用图片模型。
