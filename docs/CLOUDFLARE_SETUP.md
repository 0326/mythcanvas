# MythCanvas Cloudflare Backend Setup

This document wires MythCanvas to Cloudflare D1, R2, KV and the image-generation provider.

The repository intentionally defaults to `AI_GENERATION_MODE=mock`, so builds, previews and the Creator flow do not spend image-generation quota by default.

## 1. Runtime contract

The generation flow is:

```text
/create
  → POST /api/generate
  → validate structured request
  → resolve Character/Realm + optional CharacterVariant
  → resolve Civilization Visual DNA
  → resolve Style production profile
  → resolve OutputSpec
  → compose structured prompt layers
  → image provider adapter
  → R2 persist generated bytes
  → D1 persist generation recipe/provenance
  → return normalized image URL/result
```

Server bindings/config used by generation code:

- `DB?: D1Database`
- `ARTWORKS?: R2Bucket`
- `SESSION?: KVNamespace`
- `AI_GENERATION_MODE?: mock | http | openai`
- `AI_PROVIDER_ENDPOINT?: string` — generic HTTP mode only
- `AI_PROVIDER_API_KEY?: secret` — generic HTTP mode only
- `OPENAI_API_KEY?: secret` — direct GPT Image 2 mode
- `OPENAI_IMAGE_MODEL?: string` — defaults to `gpt-image-2`
- `OPENAI_IMAGE_QUALITY?: low | medium | high | auto`

Never expose provider secrets to browser code.

## 2. D1

Current production binding is `DB` / `mythcanvas-db`.

Apply migrations locally first:

```bash
npx wrangler d1 migrations apply mythcanvas-db --local
```

Then remote:

```bash
npx wrangler d1 migrations apply mythcanvas-db --remote
```

The migration sequence includes content, user/review/analytics data, plus:

- `0009_character_style_generation.sql`
  - `character_variants`
  - production Style fields (`prompt_template`, render/avoid rules)
  - `output_specs`
  - `reference_assets`
  - generation recipe/provenance fields

Apply `0009` before deploying code that reads the new generation columns.

### Structured generation ownership

```text
characters
  └── character_variants

styles
  └── rendering grammar / prompt template

output_specs
  └── device / ratio / exact resolution / safe-zone rules

reference_assets
  └── metadata + R2 asset_key

generation_jobs
  └── resolved recipe + prompt layers + model/reference provenance
```

Large image bytes stay in R2, not D1.

## 3. R2

Current generated artwork binding:

```json
{
  "r2_buckets": [
    {
      "binding": "ARTWORKS",
      "bucket_name": "mythcanvas-artworks"
    }
  ]
}
```

Generated assets use immutable keys under:

```text
generated/<year>/<month>/<generation-id>.<ext>
```

Reference packs should use stable ownership-oriented keys such as:

```text
characters/<character-slug>/canonical/<asset-name>.png
characters/<character-slug>/variants/<variant-slug>/<asset-name>.png
styles/<style-slug>/references/<asset-name>.png
```

The app currently serves R2 content through `/media/<r2-key>`.

## 4. Image provider modes

### Mock — default

`wrangler.json` keeps:

```json
{
  "vars": {
    "AI_GENERATION_MODE": "mock"
  }
}
```

Use mock for CI, UI development and storage/API verification without model cost.

### OpenAI / GPT Image 2 — production target

Set the non-secret mode/model variables in the Cloudflare environment:

```json
{
  "vars": {
    "AI_GENERATION_MODE": "openai",
    "OPENAI_IMAGE_MODEL": "gpt-image-2",
    "OPENAI_IMAGE_QUALITY": "high"
  }
}
```

Do **not** commit this mode change to the default repo config unless the deployment environment is intentionally ready to spend generation quota.

Store the key as a Worker secret:

```bash
npx wrangler secret put OPENAI_API_KEY
```

The direct provider calls:

```text
POST https://api.openai.com/v1/images/generations
```

with a request shaped like:

```json
{
  "model": "gpt-image-2",
  "prompt": "<resolved MythCanvas prompt>",
  "size": "1440x2560",
  "quality": "high"
}
```

The provider decodes `data[0].b64_json`, persists the PNG to R2, and stores the OpenAI request ID/model metadata in D1.

### Output specs

V1 publishable wallpaper targets:

```text
desktop-wallpaper  2560 × 1440  16:9
mobile-wallpaper   1440 × 2560   9:16
```

Draft equivalents:

```text
desktop  1280 × 720
mobile    720 × 1280
```

Do not produce one orientation and stretch/crop it as the canonical asset for the other orientation; the composition rules differ.

### Generic HTTP provider

Keep `http` mode for vendor gateways or internal generation services:

```json
{
  "vars": {
    "AI_GENERATION_MODE": "http",
    "AI_PROVIDER_ENDPOINT": "https://your-image-provider.example/generate"
  }
}
```

Secret:

```bash
npx wrangler secret put AI_PROVIDER_API_KEY
```

The HTTP provider receives:

```json
{
  "prompt": "...",
  "width": 1440,
  "height": 2560,
  "quality": "high",
  "metadata": {
    "entityType": "character",
    "entityId": "character-change",
    "variantId": "",
    "styleId": "canonical",
    "scene": "云海",
    "composition": "手机锁屏",
    "outputSpecId": "mobile-wallpaper",
    "ratio": "9:16"
  }
}
```

Supported responses remain:

1. direct `image/*`
2. JSON `imageBase64`
3. JSON `imageUrl`

## 5. Character reference packs

Production recurring characters should not rely on text-only identity forever.

Recommended Canonical Reference Pack:

```text
portrait-front
portrait-three-quarter
fullbody-front
fullbody-three-quarter
turnaround
expression-sheet
signature-props
```

`reference_assets` stores metadata/provenance and points to R2 keys.

When the reference/edit workflow is enabled, keep reference roles explicit:

```text
A = Character identity
B = selected CharacterVariant, optional
C = Style/mood reference, optional
```

GPT Image 2 processes image inputs at high fidelity; the integration should omit an `input_fidelity` override.

## 7. Local verification

Default mock flow:

```bash
npm install
npm run dev
```

For schema verification:

```bash
npm run migration:check
```

For release checks:

```bash
npm test
npm run check
```

With D1/R2 configured, verify:

1. `/api/generate` succeeds in mock mode
2. `generation_jobs` contains `output_spec_id` and `prompt_layers_json`
3. R2 contains the generated asset
4. `/api/generation/<id>` reads the persisted record
5. CharacterVariant requests fail closed when the ID does not belong to the Character
6. mobile requests resolve to 1440×2560 and desktop requests to 2560×1440

Before switching production to `openai`, verify the same flow in a controlled environment with a real `OPENAI_API_KEY` and generation quota.

## 8. Production hardening / next steps

Already present in the broader product stack: request moderation, rate limiting, session ownership, generation history, review/publish flow and R2/D1 persistence.

Still needed for the full character-art production system:

- Character/Variant admin editor
- Canonical Reference Pack upload/generation UI
- Style profile admin editor
- GPT Image 2 reference-image `/v1/images/edits` flow
- automated Character identity QA
- automated Style QA / evaluation
- asynchronous batch queue for large Character × Style × OutputSpec matrices
- cost/latency dashboards per model/style/output spec
- approved desktop/mobile paired-asset production workflow
