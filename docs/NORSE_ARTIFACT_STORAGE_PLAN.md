# Norse artwork storage and R2 migration plan

## Decision

`content-assets/norse` is the local editorial/source archive, not a public
static directory. The application architecture defines R2 as the home for
artwork bytes and `/media/<r2-key>` as the public delivery route.

The Norse delivery metadata now points to WebP objects under R2. The local PNG
and legacy JPG inputs remain only for reproducible audit and provenance; they
are outside `public/`, ignored by Git, and must never be used by page markup.

## Current inventory

The current local inventory is 126 files / about 254 MiB:

| Category | Files | Approx. size | Treatment |
| --- | ---: | ---: | --- |
| Story key-moment source PNG → WebP delivery | 74 | 150.5 MiB source | R2 stores WebP after Story visual approval |
| World desktop/mobile source PNG → WebP delivery | 16 | 60.1 MiB source | R2 stores WebP after World visual approval |
| World source/provenance PNG | 16 | 34.8 MiB | Do not expose through the public delivery prefix by default |
| Legacy/prototype/other mythology assets | 20 | 8.4 MiB | Audit separately; do not bulk-upload |

The exact source/derivative byte counts, SHA-256 fingerprints, dimensions and proposed keys are
generated by:

```bash
npm run content:art:r2:dry-run
```

The command is read-only and writes no remote state. It can write a reviewable
manifest with:

```bash
node scripts/sync-norse-art-to-r2.mjs --write
```

## Why keep source files outside `public/`?

The Norse coverage report still uses the local bytes to verify existence, PNG
dimensions, fingerprints and duplicate files. Keeping those files in
`content-assets/norse` preserves that audit contract without allowing Astro or
Workers Assets to publish the original files as `/art/*.png` or `/art/*.jpg`.

`.gitignore` is a repository hygiene rule, not an upload mechanism. The R2
objects were uploaded separately, and the application resolves only
`/media/content/norse/.../*.webp` for Norse delivery.

## Migration sequence

1. Finish the human visual review. Draft images must not become published
   canonical assets merely because they exist locally.
2. Generate and review the deterministic manifest. Delivery objects use
   `content/norse/stories/<filename>` and
   `content/norse/worlds/<filename>` keys.
3. Upload delivery files only, as WebP with immutable cache metadata. The
   current staging upload has completed for the 90 delivery objects; it is not
   a human visual approval.
   The explicit write command is:

   ```bash
   node scripts/sync-norse-art-to-r2.mjs --remote --apply --write
   ```

   This is an external write. For future reruns, confirm the destination
   bucket and backup/rollback owner first; this staging upload was explicitly
   authorized and does not change the human review status.
4. Verify every uploaded object by key, `image/webp` content type, immutable
   cache metadata and derivative SHA-256 before changing application URLs.
5. The static Norse metadata now uses the manifest's
   `/media/<r2-key>.webp` URL. Source paths use `/source/norse/...` only as
   audit labels and are resolved from `content-assets/norse`; pages never use
   those paths.
6. Run build, content coverage, provenance audit and production smoke. Deploy
   only after the Norse completion certification gate passes.

## Verification deployment status

At the request of the product owner, a verification deployment was made after
the R2 migration so the live WebP routing could be checked before final human
content approval. Worker version `8a6c15e9-dd72-4afa-ac2f-d4513ff88c7b` is live
on the production domain. The post-deploy Norse smoke passed 13/13 checks:
World and Story HTML use WebP delivery URLs, R2 headers are correct, and the
old Norse `/art` source paths return 404.

This deployment does not mark the Norse content as finally approved. The
completion certification gate remains required before changing draft/noindex
content to the final indexable/public release state.

## Source/provenance policy

The 16 pre-resize World source images are useful for reproducibility but are
not delivery assets. The existing public `/media/*` route has no provenance
authorization boundary, so they should not be uploaded under the normal public
`content/norse/` prefix. Keep them in a controlled archive or add a separate
private source bucket/admin retrieval path before storing them remotely.

The 20 legacy/prototype files require independent ownership and usage review.
They are deliberately excluded from the Norse migration script.
